# T006 — Prerenderizado del HTML en el build

- Estado: revision
- Implementa: codex
- Revisa: agy
- Depende de: T005

## Objetivo
Que el HTML publicado ya traiga el contenido de la página (prerenderizado en el build) y React lo hidrate, para que el
texto de la portada se pinte sin esperar a descargar y ejecutar el JavaScript. Medido tras T002–T004: LCP móvil 4,2 s,
elemento LCP = `<h1>` de la portada, 89 % del tiempo es «render delay» (esperando al JS).

## Alcance
- Archivos a crear/modificar: `src/main.tsx` (hidratar), `src/entry-server.tsx` (nuevo, `renderToString(<App/>)`),
  `scripts/prerender.mjs` (nuevo) o equivalente, `package.json` (solo el script `build`), `index.html` (marcador dentro de `#root`),
  `src/components/Hero.tsx` y `src/components/Contact.tsx` (estado abierto/cerrado), y cualquier componente que acceda a `window`/`document` durante el render.
- Fuera de alcance: cambiar de framework, añadir dependencias npm, cambios visuales, SSR en servidor (el sitio sigue siendo estático en GitHub Pages).

## Criterios de aceptación
- [ ] `npm run build` genera `dist/index.html` con el HTML de la página dentro de `<div id="root">` (comprobable con `grep -c "Haz una pausa" dist/index.html` ≥ 1), usando solo Vite (build SSR `vite build --ssr`) y `react-dom/server`, ya presentes.
- [ ] El cliente usa `hydrateRoot` (mantener `StrictMode`) y no hay avisos de *hydration mismatch* en la consola al cargar `npm run preview`.
- [ ] El contenido que depende de la hora actual (píldora de estado de la portada, «Abierto/Cerrado ahora» y «(hoy)» en Contacto) no se congela en el HTML: en el prerender se muestra un estado neutro (sin texto de hora, o el horario fijo «Jue a Sáb · 15–21 h») y el estado real se calcula en el cliente tras montar (`useEffect`).
- [ ] Ningún componente accede a `window`, `document`, `localStorage` o `matchMedia` durante el render (solo en efectos o manejadores), para que `renderToString` funcione en Node.
- [ ] Rutas relativas (`base: './'`) y el deploy de GitHub Pages siguen funcionando: `dist/` sigue siendo autocontenido; el bundle SSR no se publica en `dist/`.
- [ ] `npx tsc -b` y `npm run build` sin errores; `npm ci && npm run build` funciona en limpio (es lo que corre el workflow).
